# Stage 11: debugger, profiler and tunables

**Status:** implemented (branch `stage-11-debug-profile-tune`). ARCHITECTURE §37 (AJ1–AJ9). Usage: [Tools](../guide/tools.md).

Until Stage 10, finding out what a script was doing meant `print`, `rhp.emit` and reading code. Stage 11 adds three tools that work on a running program without stopping it: tunables, a sampling profiler and a debugger. None needs a native hooking package, a separate debug build or a different Lua.

## Decisions

- **AJ1 — tunables are lib variables with tags.** A tunable is a `::var` or `::ro` that already exists, not a new registry. `Rhp::range<Min, Max>`, `Rhp::step<S>`, `Rhp::unit<"...">` and `Rhp::doc<"...">` are compile-time tags. A range is enforced in the variable's setter, so a script's write, a remote `tune` and a stub-guided edit all obey it; NaN is never in range. Bounds that don't fit an integer type exactly, or `Min > Max`, fail to compile. `sandbox::tune` writes through the same setter inside a scratch request: role check, range, journal, and `revert_all` undoes it. A separate tunable registry would have needed its own undo, roles and threading story.
- **AJ2 — the profiler samples in the count hook.** Every `interval` instructions (at least 100), the hook walks the running coroutine's stack (`lua_getstack` / `lua_getinfo "Sn"`). It interns each frame's text and counts the distinct stacks: the folded format flame-graph tools read. Instruction sampling is deterministic and costs nothing between samples. Time spent in C++ bindings isn't covered, and the guide says so. The function C++ called is named after its request. Samples that can't be stored (out of memory, more than `max_stacks`) are counted as dropped, never thrown through Lua.
- **AJ3 — profiling doesn't change semantics.** The profiler arms the count hook everywhere, at `min(check interval, profile interval)`. Runs that wouldn't be checked (`cancel_checks`) skip the cancel and limit logic on those ticks (`checked_now()`). Instruction budgets count the hook's real interval. Results, limits and cancels behave as without the profiler (tested both ways). Each request remembers whether it is checked when it starts, so the profiler starting or stopping mid-run doesn't change that. A thread whose hook is out of date (a coroutine a script made before the profiler started or stopped) is re-armed on its next hook call (`sync_hook`). Ticks accumulate up to the profile interval, so a profile interval longer or shorter than the check interval, or no checks at all, still gives one sample per interval. Instruction budgets add the hook count the thread actually ran with.
- **AJ4 — the debugger pauses a request's coroutine from the line hook.** At a breakpoint, step or pause, the line hook marks the request `wait_kind::kDebug` and yields with no results. Lua suspends once the hook returns and doesn't run the hook again for that instruction on resume. The scheduler leaves the request alone until `debug_resume` wakes it. `pump()`, other requests and the game keep running. A paused request's wall time doesn't run. Stepping compares stack depths (into: any line; over: depth at most the start; out: depth below the start). Line events are only requested while breakpoints, a step or a pause exist, and a per-line bitmap rejects most lines without a `lua_getinfo`. They are on for every function then: gating them on call / return events per source was tried and dropped, because `lua_sethook` restarts the instruction countdown, so re-arming on every call starved instruction limits and cancels in call-heavy loops. A step probes the stack with one `lua_getstack` at the start depth instead of measuring the depth. At most 32 requests are paused at once; beyond that a breakpoint is a hit, so a hot breakpoint can't fill memory with suspended requests.
- **AJ5 — only a request's own coroutine pauses.** Lua can't yield across a C call or out of a coroutine the script made. So a breakpoint there (game-code handlers, script coroutines, metamethods, comparators) is reported as a `hit` event, once per place, and pause and steps wait for a line that can pause. Pausing a script's own coroutine by yielding it would hand control to the script, not the debugger.
- **AJ6 — inspection runs no Lua.** Stacks come from `lua_getstack` / `lua_getinfo`. Locals and upvalues come from `lua_getlocal` / `lua_getupvalue` on the suspended coroutine, moved to the main thread. Tables are read raw and values are rendered without `__tostring`. Evaluation resolves dotted paths in locals, then upvalues, then the module's environment (the function's `_ENV`, or the request's module when the function has none), then libs. Only lib proxies are read through (their metatables carry a `__rhp_lib` marker, and their getters are C++). Handle properties and `require` proxies aren't: a handle's property getter or a module's exports can be Lua (an `__index` on the exports table). So the only code that runs is C++ lib getters; inspecting can't change what the script does, and no debugger-side Lua sandbox is needed. The paused coroutine stopped with its top at its frame's top, so each read first makes room on it (`lua_checkstack` on the coroutine); room made from inside the hook doesn't last, because Lua restores the frame top after the hook returns.
- **AJ7 — debugger events are script events, for C++ only.** A pause is published as the script event `rhp.debug`. It stays inside the identity's sandbox and reaches C++ through `on_script_event` and clients through `client.on`. That reuses the event path, and other identities can't observe it. The sandbox's own scripts never receive it: a script handler for `rhp.debug` could itself pause and publish again, and scripts have no use for it. The event is queued and delivered after the pausing operation or `pump()`, never from inside the hook.
- **AJ8 — over the wire, each tool acts on the caller's own sandbox.** `kTunables` and `kProfile` need observe; `kTune` and `kDebug` need patch (pausing changes behaviour). `kTune` and the debugger actions that change what scripts do (`break`, `pause`, `continue`, steps, `reset`) are audited as `script_executed`; reading (`kTunables`, `kProfile`, and the debugger's `paused`, `stack`, `variables`, `evaluate`) isn't. Every session that sets breakpoints or pauses joins the identity's debugging sessions; when the last one ends, the debugger resets (paused scripts run on). So one of two editors detaching doesn't drop the other's breakpoints. The session that started the profiler owns it, and its end stops it. A profile reply holds the stacks with the most samples up to a quarter of `limits.max_frame` and counts the rest as `truncated`, so a large profile can't produce a frame the peer refuses. Protocol revision 6.
- **AJ9 — rhp-cli is the front end, including DAP.** The REPL gets tunables, profile and debugger commands, and an expression, `call`, `load` or `reload` whose own request pauses (matched by the pause's request label) moves to the background. `rhp-cli dap` speaks the Debug Adapter Protocol on stdin / stdout and maps source files to module names under `--root`. Paused requests are threads (a placeholder thread when none is paused, since editors expect one), and a thread's frame and variable references are valid until that thread runs on. The stdin reader thread owns its own state, because it can outlive the server while blocked in a read. Malformed framing ends the adapter (no resynchronizing a byte stream). It uses a small JSON codec over `Rhp::value` (no new dependency) and `platform::binary_stdio` for byte-counted framing on Windows.

## Alternatives

- **A debug hook via `debug.sethook` or a Lua-side debugger (mobdebug style):** needs the `debug` library in the sandbox (it can break out of `_ENV`), and runs the debugger's own Lua inside the program it debugs.
- **Stopping the whole program at a breakpoint:** what native debuggers do. It freezes the game, and every other script with it.
- **Time-based sampling (a timer thread interrupting the VM):** needs signals or thread suspension per OS and a lock-free stack walk; instruction sampling is portable and safe.
- **A tunables registry separate from libs:** duplicates names, roles and undo; tags on `::var` give the same metadata without them.

## Consequences

The line hook costs nothing while no breakpoint, step or pause exists. While one does, every line event takes a bitmap check, and lines that have a breakpoint somewhere also a `lua_getinfo` ([benchmarks](../benchmarks.md#stage-11-tools)). The profiler adds a stack walk per sample. `RHP_ENABLE=OFF` keeps the API, which reports `kDisabled`. Not done: conditional breakpoints, setting variables from the debugger, a debugger or profiler for release channels over the wire.
