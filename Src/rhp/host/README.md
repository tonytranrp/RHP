# host — layer 5

`Rhp::host<Cfg>`: a program that accepts remote Lua. The template is a thin shell over an engine compiled once (`host.cpp`, `engine_network.cpp`, `engine_identities.cpp`, `engine_requests.cpp`). Target `Rhp::host`; depends on `config`, `session`, `script`, `event` and `release`. Usage: [host and client guide](../../../Docs/guide/host-and-client.md).

| Header | What |
|---|---|
| `host.hpp` | `Rhp::host<Cfg>` (`Cfg`: a `host_configuration`, which signs its scripts unless it is at hardening `kDev`): `install<Lib>()`, `pump()`, `on<E>()` / `on_any()`, `on_script_event()`, `on_blob()`, `serve(release::manager&)`, `set_enabled()` / `enabled()`, `port()`, `gateway_port()`, `advertise()`, `discovery_status()`, `sessions()`, `identities()`, `logger()` / `clock()` (the config's logger and clock instances) |
| `detail/engine.hpp` | `host_options` (idempotency cache, inbox capacity, `tls`, `gateway`, `http_require_binding`, `handler_errors`, `remote_events_per_pump`, `ack_delay_ms`, `hardening`, `observe_limits`, `dev_session`, `app` / `env` / `host_id`), `blob_view` / `blob_fn`, the type-erased `setup` and the engine's free functions |
| `detail/releases.hpp` | the bridge `serve` uses: answers the release ops with a `release::manager` (`releases.cpp`) |
| `host.cpp`, `engine_network.cpp`, `engine_identities.cpp`, `engine_requests.cpp`, `detail/engine_impl.hpp` (private, not installed) | the engine: construction, setup calls, goodbye and `pump()`; its network thread (sessions, resume, cancels, the gateway's sink); identities, events and subscriptions on the pump thread; requests and their ops |
| `gateway.cpp`, `detail/gateway.hpp` (private, not installed) | the HTTP listener: routing, per-key logical sessions, the replay guard; the engine implements its `gateway_sink` |

```cpp
Rhp::host<> host{Rhp::endpoint::listen("127.0.0.1", 7777),
                 *Rhp::security::keyring::from_file("keys.txt"),
                 *Rhp::security::trusted_signers::from_file("signers.pub")};
(void)host.install<game_lib>();
auto audit = host.on_any(Rhp::audit::file_sink{"rhp_audit.log"});
(void)host.on_blob("configs", [](const Rhp::blob_view& b) -> Rhp::result<void> { return game::load_config(b.bytes); });
while (running) { host.pump(); game::update(); }
```

## What it does

- **Sessions:** the network thread authenticates every connection (`config<>::auth`) and hands requests to `pump()` through SPSC rings. Unauthenticated connections, native and HTTP together, go through one `session::admission`: `limits.pending_handshakes` at a time, `limits.handshakes_per_source` from one IPv4 address or IPv6 /64, nothing sent within `limits.first_byte_ms` closes one, and a new connection takes the slot of the oldest silent one, else of the oldest one stalled for a quarter of `limits.handshake_timeout_ms`, rather than being refused. `auth_failed` names the key a refused client tried (its hello's, or its HTTP proof's).
- **Identities:** one sandbox per key identity, created on its first session. When its last session ends everything it did is reverted and the sandbox closed — unless an admin pinned some of its modules (`pin`): those, and the modules they require, stay (with the calls running in them); the rest is reverted, and the shared library tables (`string`, `table`, ..., the string metatable) are restored (`sandbox::restore_builtins`, decision AL3), so a pinned module must not rely on builtins it or others changed. `revert` / `unload` / `revert_to` refuse to touch pinned modules. Asynchronous calls still running are handed on (`release_async`) so a late success is still taken back.
- **Roles and signatures:** each request's least role is checked (`wire::required_role`); `exec`, `load` and `reload` must carry a signature by a trusted signer (`config<>::signer`, Ed25519 by default) unless the session is observe. A signature that is present must verify. Both checks (the network thread's pre-check in `on_message` and the pump's in `check_signature`) pass the signer policy a `security::signature_context` (`engine::signature_context_for`: the session's identity and role, `host_options::app` / `env` / `host_id`, the wall clock and the host's hardening); a trust with a context-taking `verify` (`security::certified`) uses it, others are called as before. `env` defaults to `"prod"` at hardening production and `"dev"` below (`hardened()`).
- **Capability scopes** (decision AL13): the authenticator's grant carries the identity's scopes (`auth_grant::scopes` / `http_grant::scopes`, a keyring line's optional fourth column; everything by default). They become the sandbox's `sandbox_options::scopes` (`sandbox_options_for`: libs, caps, patch points, events), every request's op is checked right after its role (`op:<wire name>`, kForbidden "needs scope op:x"), and `kSubscribe` refuses an event the scopes don't allow (C++ `lua_event`s and the identity's script events; a `*` subscription forwards only allowed names). Scopes are per identity: one keyring entry, one set, whichever session opened the sandbox. A signature that carries scopes (an operator certificate's, `security::certified`: the trust stores them in `signature_context::scopes`, on both the network pre-check and the pump's check) narrows its request: `check_signature` refuses an op they don't allow (kForbidden "... the signature's certificate lacks it") and the exec / load / reload runs under `scope_set::intersect(identity, certificate)` through `sandbox::narrow` (`narrowed_run`), so what a narrowed module registers stays narrowed and a narrowed exec can't register handlers (see `Src/rhp/script/README.md`). Unsigned ops (call, unload, ...) are the identity's alone.
- **Rate limits** (per identity, on the pump thread, both 0 = off; each identity's own limits, `limits_for(role)`: observe's are `observe_limits`, capped by `kObserveCaps` from hardening `kLan` up): `limits.request_rate` is a token bucket on the host's clock (`config<>::clock`), checked when `pump()` takes a request from the network (`admit`); one that finds no token is answered `kLimitExceeded` (HTTP 429), audited and never run. A blob takes one token, for its first chunk: a chunk is free only when it goes on from where the session's last admitted chunk of that transfer ended, within the total its first chunk announced; any other chunk (a forged transfer id or offset) takes a token like any request, and a transfer that fails stops being free. `limits.pump_requests` starts at most that many of an identity's requests per `pump()` (`start_queued`): identities take turns, one request each per round, the one after the last pump's first going first; the rest wait in arrival order in their identity's queue (4096 requests and 64 MiB at most, then `kLimitExceeded`), and a session's waiting requests end with it.
- **Idempotent retries:** replies are kept per session by the client's idempotency key (`host_options::idempotency_cache` / `idempotency_bytes`), so a resent request runs once.
- **Cancels:** a client's cancel is relayed to the running request from the network thread; a cancel-enforcement timer re-applies recorded cancels to whatever runs inside `pump()`, and runs only while a cancel is recorded.
- **Events:** `script_executed` for every request that runs code or changes state (refused ones too), sessions, auth failures, blobs, reverts, `handler_failed`, `release_changed` — on the pump thread. `on_script_event` reports every identity's `rhp.publish` (each sandbox's script events are forwarded through `sandbox::on_script_event("*")`).
- **Subscriptions:** `kSubscribe` / `kUnsubscribe` (observe) name a C++ `lua_event` (the engine is itself an `event_listener`, attached while any session wants that event, detached when the last one unsubscribes or closes and when the engine stops) or the session's identity's script events. Deliveries are `kEvent` frames with `req` 0, at most `host_options::remote_events_per_pump` per session per pump; the next one reports how many were dropped. Subscriptions belong to the host session and survive a resume.
- **Handler failures:** `host_options::handler_errors` is every sandbox's default policy; a failure is logged, published as `handler_failed` and sent to the identity's sessions as an output line.
- **Blobs:** `on_blob(sink, fn, role)` (admin by default); chunks are checked (sink, role, `limits.max_blob`) on the first one, buffered, and the whole blob goes to `fn` on the pump thread. The sink's result is the client's answer. One transfer per session; a new one replaces a transfer the client gave up on.
- **Releases:** `serve(manager)` routes `release_apply` / `confirm` / `deactivate` (admin), `release_status`, `revoke` and `trust` (observe) to a `release::manager` that `pump()` pumps, raised to the host's hardening level (`manager::harden`); its changes are `release_changed` events. The manager must outlive the host. A script whose signer's key the manager's identity revocations name (`manager::identities()`) is refused (`kRevoked`); the host finds the key through the trust policy's `find(name)` (`trusted_signers`), so a policy without one isn't checked.
- **Tools:** `tunables` / `tune`, `profile` and `debug` act on the caller's own identity sandbox. When the profiling session ends the profiler stops; when the last debugging session of an identity ends its breakpoints go and paused scripts run on. Debugger actions that change what a script does are audited.
- **Reverse mode:** with a dial endpoint the host dials a listening client and redials (capped exponential backoff, full jitter, `limits.backoff_min_ms` / `backoff_max_ms`) whenever that fails or the session ends; a lost link is redialed to resume the same session. A dialing host opens with a ping.
- **TLS:** non-loopback peers get TLS 1.3 (`config<>::tls<>`), `require_tls` everyone; `host_options::tls` holds the certificate (default: ephemeral self-signed). Events say `tls`.
- **Resume:** a lost link keeps the session for `limits.resume_ms`; the client's new connection takes it over (`session_resumed`), nothing is reverted or run twice. Shutting down sends every session a goodbye with a reason first, and the gateway answers the HTTP requests in flight.
- **Kill switch:** `set_enabled(false)` (any thread) closes every session, native and HTTP, with `kDisabled` (identities revert as on disconnect; pinned modules stay), refuses new connections (reported as `auth_failed`), stops a reverse-mode host's dialing, and makes `pump()` run no scripts: requests are answered `kDisabled`, and no handlers, tasks or release channels run until `set_enabled(true)`, which resumes everything (and dials again). The flag takes effect at once; the network's part is posted to the network thread in call order. Patches held by pinned modules or release channels still run when game code hits them (`revert_all` and `release_deactivate` remove them first).
- **HTTP:** `host_options::gateway` opens a separate TCP / HTTPS listener ([networking guide](../../../Docs/guide/networking.md)). Per-request proofs authenticate the same identities (optionally bound to the TLS channel; `http_require_binding` insists) and every authenticated answer carries an `X-RHP-Proof`; each key gets one logical session that ends after `limits.gateway_idle_ms` with nothing in flight, measured on the host's clock. Connections share the native unauthenticated-handshake budget until their proof checks out. Audit records carry each request's own caller.
- **Hardening** (decisions AL1, AL2, AL4): the host runs at the strictest of `RHP_HARDENING`, `config<>::hardening` and `host_options::hardening` (`hardened()` in `host.cpp` settles it with the limits). Above `kDev`: `insecure_lan` endpoints (native and gateway) and dev sessions are refused, `signer<unsigned_scripts>` doesn't start, admin sandboxes get patch's libraries (`sandbox_options::admin_stdlib`), and observe identities run under `host_options::observe_limits` (default: the config's) capped by `kObserveCaps`. At `kProduction` also: observe code must be signed, `kDebug` is refused, `advertise()` is refused, the gateway needs `http_require_binding`, and every identity's limits are capped by `kProductionCaps`. A refused start is reported by `port()` (`kForbidden`), a refused gateway by `gateway_port()`.
- **Dev sessions** (decision AL7): `host_options::dev_session = "app"` in a dev build at hardening `kDev`, listening on a loopback address (network transport) or local IPC, with the HTTP gateway (if any) on a loopback address too, since it accepts the same identities: `host<Cfg>` adds a fresh admin PSK identity (`dev-session`) and Ed25519 signer to its authenticator and trusted signers (`psk_keyring` and `ed25519` only), and once listening the engine writes `security::dev_session_path(app)` owner-only (`rhp-cli connect --dev app` reads it; when it can't, the host stops listening, gateway included); the destructor removes it. Admin, because the file is the developer's own: any process that can read it runs as the same user and could already change the game.
- **Discovery:** `advertise(options)` publishes through `Cfg::discovery_t`; `include_libs` separately publishes library names. Later provider errors: `discovery_status()`.

## Rules

- `install`, `on_blob`, `serve`, `advertise` and `pump` belong to one thread (the pump thread; any one thread before the first `pump()`, `kInvalidArgument` from another after it); so does `discovery_status` with `io<zero_threads>`. `on` / `on_any` / `on_script_event`, `set_enabled` / `enabled`, `port`, `gateway_port`, `sessions`, `identities` are thread-safe.
- Lock order for C++ events: an event's own mutex, then the engine's `program_mutex_` (fires from other threads queue there); attach and detach never run under `program_mutex_`.
- Nothing from `session` or the engine leaks into `host.hpp`; config policies are type-erased into `setup`. Gateway types stay in the private `detail/gateway.hpp`.
- The destructor sends goodbyes, stops the network and reverts every identity, pinned modules included.
- What a build's level doesn't allow is compiled out with `if constexpr` on `kBuildHardening` (dev sessions outside dev builds; unsigned observe code and the debugger op in production builds): runtime checks use the effective level, never the build's alone.
- `RHP_ENABLE=0`: the host is inert (every result-bearing call — `install`, `on_blob`, `serve`, `port`, `gateway_port`, `advertise`, `discovery_status` — reports `kDisabled`; `enabled()` is false; `sessions()` / `identities()` return 0), no engine is built.
