# script — layer 3

The script engine: PUC Lua 5.5 (built as C++), the `Rhp::lib<>` binding DSL, patch points, events, the undo ledger and the per-identity sandbox with its scheduler, tools and test hooks. Namespace `Rhp::script`; the DSL front is in `Rhp::` (`Rhp::patch_point`, `Rhp::lua_event`, `Rhp::convertible`) or re-exported there (`Rhp::lib`, `Rhp::undo`, `Rhp::irreversible`, `Rhp::requires_role`, `Rhp::cap`, `Rhp::range`, `Rhp::step`, `Rhp::unit`, `Rhp::doc`). Target `Rhp::script`; depends on `core`, privately on Lua. Usage: [exposing C++](../../../Docs/guide/exposing-cpp.md), [writing scripts](../../../Docs/guide/writing-scripts.md), [scheduling and events](../../../Docs/guide/scheduling-and-events.md), [tools](../../../Docs/guide/tools.md).

```cpp
float gravity = -9.81f;
void spawn(std::string_view kind, int n);
void despawn_last(std::string_view kind, int n);
using game_lib = Rhp::lib<"game">
    ::var<"gravity", &gravity, Rhp::range<-50.0, 0.0>, Rhp::unit<"m/s2">>
    ::fn<"spawn", &spawn, Rhp::undo<&despawn_last>>;

Rhp::script::sandbox box;
(void)box.install<game_lib>();
auto g = box.exec<double>("return game.gravity");                     // -9.81
auto mod = box.load("low_grav", "game.gravity = -1.6 game.spawn('crate', 2)");  // journaled
(void)box.unload(*mod);                     // despawn_last("crate", 2), then gravity is -9.81 again
auto bad = box.exec("game.gravity = 10");   // fails: outside Rhp::range, nothing written
```

## How a binding call flows

```text
Lua: game.spawn("crate", 1)
  → lib proxy __index (the members table: a raw hit) → C closure call_fn<Handles, Entry> (upvalue: "game.spawn")
  → role check (check_access: check_role, plus one bit test for an Rhp::cap<>) → pull args (pull_args: each one a span, a struct view, a handle, an
    optional handle, else Rhp::convert; the first that doesn't fit raises, labelled with its position)
  → invoke C++ (call_guarded: C++ exceptions from the call or from pulling become labelled Lua
    errors, raised after the try block)
  → ledger records undo<G>(result or arguments) / irreversible for the current module
    (record_binding_effect) → push results
  (an Rhp::async<T> result: the request suspends until it arrives, then the same steps)
```

- **Plain bindings** (`plain_binding_v`: synchronous, no `undo<G>` / `irreversible`, every parameter a bool, integer, floating point number, `std::string_view` / `std::string`, `std::span<const T>` or handle, by value or const reference) take `call_plain`: one `stack::read_args` reads every plain argument by type into `arg_slot`s (no `result<T>` per argument), handles are pulled as usual, then the call, exceptions and `push_return` as above. An argument that doesn't fit sends the call down the general path (`invoke_fn`), which raises the error it always has: the two paths can't disagree. A new kind of plain argument is a `plain_arg<T>` specialization plus a case in `stack::read_args`.
- **Lib proxies** (`puc_lua/lib_proxy.cpp`): a locked userdata whose `__index` is the members table (functions, sub-libs: a raw hit after one table-valued metamethod), whose metatable's `__index` is `lib_var_index` (variables: one C call, the getter run in its frame); `__newindex` calls the setter. The test bridge reaches the getters and setters as upvalue 1 of those two C functions (`testing.cpp`).
- Handle properties (`get_property`) are C functions without upvalues, labelled at compile time (`static_label`): the handle's `__index` (`handle_index`, `stack.cpp`) runs one in its own frame, the handle at index 1, instead of a nested `lua_call`.
- **View bindings** (`returns_view_v`: a result that is `std::span<T>`, or a pointer / reference to a `::view` type, `Rhp::result<>` peeled) take `call_view`: the arguments are pulled as on the general path and copied (`capture_t`) into a `binding_source` built inside the view's userdata (`stack::push_host_view`, `attach_view_source`, which resolves it once: errors raise at the call, a null pointer gives nil). The view keeps no pointer: every access calls `source->find()`, which checks handle arguments with `is_alive` and calls the binding again (`resolve()`, which says why there is no memory, runs only when `find` fails). Children (slices, array and struct fields, typed views of buffers) are nodes pointing at their parent node (kept alive by uservalue 1) with an offset; `locate` walks up to the memory (`views_impl.hpp`).
- **Span parameters**: `std::span<const T>` is plain (`plain_arg`, `arg_kind::kSpan`: `read_span_arg` finds a view's memory, or a string's bytes); a table, a mutable `std::span<T>` and every mismatch go through `pull_arg` → `stack::to_span` (a table is copied into a temporary userdata left on the stack for the call; a mutable host span is journaled first). A struct view parameter (`T`, `const T&`, `const T*`) is `stack::to_object`.

## Requests and the frame

```text
exec / load / call ─▶ request (coroutine) ─▶ runs until done, error, rhp.wait/sleep, an async binding, or slice end
                                              │ suspended: the operation returns early
pump() ─▶ queued C++ events ─▶ queued script events ─▶ frame callbacks and due timers ─▶ arrived async results
       ─▶ ready requests: woken waiters, tasks, waits that ended (round robin, within slice_us)
       ─▶ faults · handler failures · cancels · deferred lifecycle operations · collected task handles
       ─▶ handler failure reports · script-event listeners · on_result callbacks
```

- A failing load or call faults its module; a scratch (exec) request reverts only its own effects.
- A failing handler (timer, frame callback, event handler, task) follows its `handler_error_policy`: `report` (default) undoes only that call's effects, `remove` also drops the handler, `fault` faults the module. A memory stop always faults. Patch handlers keep faulting.
- Every request's end goes through `request_ended` (from `complete` and `abandon_requests`): it releases waits, wakes joiners, finishes task records and clears the overlap guard of its schedule entry. Firing loops snapshot keys and look each one up again; a record is never written through a reference held across a Lua allocation (a collection can run finalizers that remove it). Finalizers that `lua_close` runs can't schedule, subscribe or spawn, and their effects are undone at once.
- A task never runs inside its spawner (it starts at the next pump) and its instruction and wall budgets reset on every resume. A suspended task is abandoned at once when cancelled; a running one is stopped through the cancel path.
- Lifecycle operations from inside a run are deferred to the end of the outermost operation.
- `sandbox_options::on_output` (print with its request and module), `on_result` and `sandbox::pending(request)` exist for `Rhp::host`, which answers network requests that suspended once `on_result` reports them.

## What untrusted code can't do (Stage 13, AL3)

Measured holes, closed for every hardening level ([decisions](../../../Docs/decisions/stage13-security.md)).

- **Finalizers.** Lua runs `__gc` with its hooks off (`lgc.c` `GCTM` clears `allowhook`), where no limit, cancel or deadline reaches, so a finalizer that loops would hang the pump. Observe and patch identities get a `setmetatable` that refuses a metatable with a `__gc` field (`lua_safe_setmetatable`, a raw lookup, any value); Lua marks an object for finalization only when it gets a metatable that has `__gc` at that moment (`luaC_checkfinalizer`), so a `__gc` added to the metatable afterwards never runs. Admin keeps the standard one (and `debug.setmetatable`) where it has the whole standard library. `<close>` variables run with hooks on: they work, and stay limited.
- **Admin's standard library** (decision AL2). An admin sandbox opens all of Lua's libraries (`io`, `os`, `package`, `debug`, `collectgarbage`, `string.dump`, finalizers) only in a dev build (`RHP_HARDENING=dev`; `open_libraries` compiles that branch out of the others) and only while `sandbox_options::admin_stdlib` is true (the default; a host sets it from its hardening level). Otherwise admin gets patch's libraries and keeps its own rights (admin-tagged bindings, the admin ops). Above dev the code isn't even in the binary: `cmake/lua/lua_cxx.cpp` leaves out `ldblib.c`, `liolib.c` and `loadlib.c` (an `#if` on `RHP_HARDENING` choosing sources; `linit.c`'s table opens nothing in their place, so `luaL_openlibs` leaves `io`, `package`, `debug` and `require` nil), and `cmake/RhpLua.cmake` patches `loslib.c` so `os.execute`, `exit`, `getenv`, `remove`, `rename`, `setlocale` and `tmpname` (functions and table entries) are compiled out; `os.time`, `clock`, `date` and `difftime` stay (a sandbox exposes time and clock, which the test engine fakes). Keeping `loslib.c` with seven `#if` patch sites was leaner than a time and clock of RHP's own (`os.time{...}` normalizes a date table through `mktime`).
- **Work in C.** Pattern matching backtracks in C (`max_expand` / `min_expand` loop, only the recursion depth is limited) and plain find is O(n·m) (`lmemfind`), where no hook fires. `cmake/RhpLua.cmake` patches `lstrlib.c` like `lvm.c` (each site matches exactly once or configure fails): each pattern item `match` visits (at its `init:` label, so the tail-call `goto init` continuations count as calls do), each character an expansion or `%b` scans (inside `max_expand`'s loop, not after it), and every 32 bytes a bracket class scans for one character (`singlematch` and `%f`: a class is O(its length) per character) or a back-reference or a find candidate compares is a step, counted down in the match state (or `lmemfind`'s local); every 4096 steps `rhp_lua_steps_due` (`cmake/lua/lua_cxx.cpp`) calls the state's step function (`internals::set_step_function`, kept in the registry) directly, on a thread that has a hook, outside hooks and finalizers. `sandbox_impl::charge_steps` (`hook.cpp`) is a count event without the profiler and the time slice (C can't yield): `check_limits` charges the steps to every run's instruction budget, checks cancels and the wall limit and raises the sticky stop, as `count_hook` does. With nothing armed a step costs a decrement and a branch; a state without a step function (a plain one) only counts down.
- **Known limits: other work in C** (not charged). `table.sort` without a comparator compares in C (`ltablib.c` `auxsort`, `lua_compare`): n log n comparisons, each O(length) for two strings (`l_strcmp` has no shortcut for a string compared with itself), so sorting many references to one long string can hold the pump for minutes (2000 references to a 1 MiB string: 10 s in a Debug build, past a 100 ms wall limit); with a comparator every comparison is a Lua call and is checked. `load` parses a chunk in C, O(its size), so the memory limit bounds it. A `<` / `<=` between two long strings is one instruction that scans both. No limit, deadline or cancel reaches them until they return; charging them would take a step counter in `sort` (which keeps no state to count in) and in `lvm.c`'s string comparisons.
- **Lasting handlers.** Observe identities can't register timers, frame callbacks, subscriptions or tasks (`rhp.timer`, `after`, `every`, `every_frame`, `every_frames`, `on`, `once`, `on_error`, `spawn`): those change the host's schedule. `open_libraries` puts `lua_needs_patch` in their place (`kForbidden`, "needs role patch", named after the builtin, like `rhp.patch`'s check), so nothing is checked per call, and `stubs::rhp_api` leaves them out for observe. What ends with the request still works (`rhp.wait`, `sleep`, `next_frame`, `wait_event`, `publish`).
- **How many handlers** (AL4). `limits.handlers` caps the timers, frame callbacks, subscriptions and unfinished tasks alive in one sandbox: one more raises `kLimitExceeded`, named after the builtin (`refuse_over_handlers`). `handlers_` counts them where they are added and removed (`add_schedule` / `remove_schedule`, `subscribe` / `unsubscribe`, `spawn` / `finish_task`), so `rhp.off`, a spent one-shot timer or `once` subscription, a task's end and a revert all make room, and a check costs a comparison.
- **Addresses.** `tostring` (`luaL_tolstring`'s default case, so `print` and `%s` too), `string.format`'s `%p` and the description of a result RHP can't convert (`collect_results`) show `rhp_lua_topointer`'s value (`cmake/lua/lua_cxx.cpp`; `lauxlib.c` and `lstrlib.c` are patched to call it): SipHash-2-4 (`Rhp::utils::siphash24`, so `Rhp::lua` links `Rhp::utils`) of the address under a 128-bit key per sandbox (`Rhp::platform::random_array`, kept in the registry by `internals::set_address_key`), in the platform's `%p` format. Lua never moves objects, so the value is stable for the object's life; 64 bits keep live objects apart in practice. A plain state (no key) shows addresses as upstream. RHP's own `__tostring`s that show an address hash it the same way (`rhp_lua_hide_address`, through `stack::shown_address` / `internals::shown_address`): a handle type `std::format` can't show (its userdata, so it matches `%p`) and a struct view (its host object, so two views of one object agree). Table iteration order still depends on addresses for table, function and userdata keys.
- **Changed builtins.** `string`, `table`, `math`, `utf8`, `coroutine`, `os`, `rhp`, `rhp.buffer` and the string metatable are shared by every module of the identity and changeable in place (`string.upper = f`, `getmetatable("").__index = t`). `snapshot_builtins` copies them (shallow, with their metatables, in the registry under `kBuiltinsKey`) when the sandbox is made; `revert_all` (an identity's revert, a session's end) calls `restore_builtins` after unloading everything: added fields go, changed and removed ones come back, the metatable is the original. They stay plain tables (a read-only proxy would add a lookup to every `string.x` and string method call), so nothing costs anything until the revert. A change RHP makes later goes into the copy with `keep_builtin` (`enable_testing`'s fake `os.time` / `os.clock`). Unloading one module doesn't restore them: the tables belong to the identity. `sandbox::restore_builtins()` restores them alone, for an owner that reverts an identity but keeps some of its modules (a host's pinned ones).

## Capability scopes (Stage 13b, AL13)

`sandbox_options::scopes` (an `Rhp::scope_set`; a host passes the identity's keyring column) bounds what one identity reaches. The default allows everything and costs nothing.

- **`lib:`** — `install_lib` skips a lib the scopes don't allow (`install<L>` succeeds; the global, its stubs, `api()` entry and tunables are simply not there). A sub-lib a deny pattern names (`!lib:game.debug`) is left out of its parent by `lib_builder` (`scope_denies`), and `api()` / `tunables` leave it out too.
- **`cap:`** — every distinct `Rhp::cap<"name">` gets one bit of a 64-bit mask the first time a lib carrying it is installed (`assign_cap_bit`, process-wide, under a lock; names after the 63rd share bit 63, whose hit falls back to matching the name). `install_lib` ORs the bits the scopes deny into `context::denied_caps_`. The trampoline (`check_access`) does one relaxed load of the binding's bit and one AND against that mask after the role check; a binding without a cap compiles to `check_role` alone (`if constexpr`). A hit raises kForbidden "needs capability <name>", labelled like the role errors.
- **`patch:`** — `rhp.patch` checks the point's id once, when it attaches (never per hit). `api()` lists only allowed points.
- **`event:`** — `resolve_event` (rhp.on, once, wait_event) refuses an event the scopes don't allow, C++ `lua_event`s and script events alike; `rhp.on_error` (the identity's own `rhp.handler_failed`) is exempt. `api()` lists only allowed events. `rhp.publish` isn't checked: a script's own events stay in its sandbox.
- **`op:`** — the host's request check (`Src/rhp/host`); the sandbox doesn't see ops.
- **Narrowing** (`sandbox::narrow`, `puc_lua/narrowing.cpp`): scopes the next exec / load / reload run with on top of `sandbox_options::scopes` (a host passes an operator certificate's). They are kept per exec request (`(scratch, request)`) or per module revision (`(module, revision)`) in `narrowed_`, and follow the running code's owner: `active_scope` looks the owner up (only while `narrowed_` isn't empty) and sets `active_narrowing_`, and `context::denied_caps_` becomes the sandbox's bits (`base_denied_caps_`) plus the narrowing's, so a capped binding still costs one mask test. `scope_allows` / `scope_denies` check both (`rhp.patch`, `resolve_event`, the cap overflow bit). A revision's timers, event and patch handlers, tasks and `sandbox::call`s carry its owner, so they stay narrowed; `revision_source::narrowing` makes a rollback narrowed as the revision it goes back to was. A narrowed exec can't register lasting handlers or patches (`refuse_narrowed`, from `refuse_over_handlers` and `rhp.patch`): the scratch module is shared by every exec of the identity, so they would outlive the narrowing. Libs aren't taken away for one run: a narrowing that denies a lib or sub-lib the sandbox has refuses the operation (`check_narrowed_libs`, kForbidden naming the lib). Entries go when their request ends or their revision is replaced, abandoned or unloaded (`forget_narrowing`, applied once no run is active).

## Rules

- `lua.h` / `lauxlib.h` / `lualib.h` only in `puc_lua/*.cpp` (and `Tests/bench` raw-Lua twins). Headers forward-declare `lua_State`.
- Lua is compiled as C++: errors throw. Never put `catch (...)` around Lua API calls; catch `std::exception` only and raise after the `try` block.
- Yields jump, errors throw (`cmake/lua/lua_cxx.cpp`, `RHP_LUA_JUMP_YIELDS`): a yield `_longjmp`s back to its `lua_resume`. With the MSVC ABI only on x64, never under TSan; a process with a CET shadow stack (an executable linked `/CETCOMPAT` on a CPU that has one; `RDSSP` decides once per process) throws instead (`rhp_script_cet_tests`). So a C function that calls `lua_yield` / `lua_yieldk` (itself or through a helper, `detail::yield_async` included) holds no C++ object with a destructor at that point: use `string_view`s into the Lua stack. Yields from the hook are fine, the count hook's slice yield and the line hook's debugger pause (Lua jumps after the hook returns).
- Allocation (`sandbox_impl::allocate`): blocks up to 128 bytes come from `small_alloc` (per-size-class slabs of 4 KiB in 64 KiB regions, taken from `sandbox_options::memory` when set); larger ones from the C heap or that resource. Where a block lives follows from the size Lua passes back, so a block never moves between the two except through an allocation and a copy; a small block shrinks in place when no smaller slab has room (slab blocks are freed by address). Accounting (`memory_used_`, the limit, the sticky memory stop, the meter's counters and kinds) is in Lua's sizes, as before. The innermost run budget is cached in `budget_` (`active_scope` keeps it), so an allocation never walks `running_`. Under AddressSanitizer there is no pooling, so use-after-free in Lua objects is still caught. Regions all go back when the allocator is destroyed, after `lua_close`.
- Every Lua call made from C++ outside a running script goes through `stack::run_protected` (or `stack::call`, which is there for users' code such as a `Rhp::convert`; RHP itself uses `run_protected`), so an out-of-memory under a memory limit becomes an error, never a panic. One exception, `sandbox::call` (`call_unprotected`): its setup runs outside a protected run only when nothing in it can raise or throw (the function's name is an interned key from `call_keys_`, the exports table has no metatable, the arguments are scalars, a spare record and coroutine are at hand, every container used has capacity); `lua_resume` protects the call itself, and anything but a normal return with scalar results (an error, a stop, a suspension, strings or tables) finishes inside a protected run. Keep it that way when changing what `start_request`, `prepare_request`, `resume_request` or `complete`'s success path do. It follows that nothing may raise on the main state while a request's coroutine runs (there may be no protected run on it to catch the error, and Lua aborts): code that allocates for a running script does it on the script's own thread (`rhp.spawn` makes its coroutine there), or inside `protect` / `run_protected` (deliveries, patch handlers, undos).
- The cancel hook counts at safe points while armed: `sandbox_impl::install_hook` sets a count-only hook with `internals::set_safepoint_hook` (no hook mask; the `lvm.c` patched by `cmake/RhpLua.cmake` charges each loop back-edge its body's length and each Lua call 1, and arms the hook for one instruction when the count runs out), so `limits.instructions` is a bound counted that way, not an exact count. The meter, the profiler and line events use `lua_sethook` (every instruction). Arm it only through `arm_hook` / `operation_scope` / `start_request` and `limits.cancel_checks` (`cancel_scope`); the profiler and the debugger change its count and mask through `rearm_all`. A count that isn't due is counted down inline (`rhp_lua_traceexec` in `cmake/lua/lua_cxx.cpp`, used by `lvm.c` only); due counts, line events and hook yields go through upstream's `luaG_traceexec`, so hook calls and the exact instruction meter are unchanged. That file spells out onelua.c's include list: keep it in step when Lua is updated (an `#error` on the release number says so).
- Scheduler caches (`sandbox_impl.hpp`): anything that can make a timer / frame callback due sooner sets `schedule_dirty_`, anything that can wake a suspended request sooner sets `requests_dirty_`; otherwise `pump()` skips it.
- Request records, map nodes and coroutines are pooled: a `request_record` is a `request_state` plus three pooled strings; `reset()` assigns the state whole and clears the strings (they keep their buffers, so a call's label is built in place without `std::format`). A new field goes in `request_state`: a `static_assert` on the sizes fails otherwise.
- A request enters `requests_` (the scheduler's map) only when it first suspends (`list_request`, from `step`); until then its map node waits in `unlisted_` (`listed` says which). Tasks, which start at a later pump, are listed at once. So code that asks whether a request exists checks `live(id)` (listed, or on the run stack), not the map; `rearm_all` reaches listed coroutines only, so a request re-syncs its hook (`sync_hook`) when it is listed.
- The handlers of one delivery (`deliver_now`) share one record and coroutine while they return normally: `restart_request` gives the next handler a new request id, owner, budget and policy in the same coroutine (re-armed), so effects, `report` undos, cancels and failure reports stay per handler. A handler that suspends keeps the record as its own request and one that fails closes it; the next handler starts a new one. A scope guard hands an idle record back (`release_kept`) if the delivery unwinds.
- Asynchronous bindings (`Rhp::async<T>`, `puc_lua/async.cpp`): a completing thread only posts to `async_inbox`; waking and settling happen in `pump()` on the sandbox's thread. A request waiting for one has `wait_kind::kAsync` and holds the call; a call whose request is gone goes to `detached_async_` until its result arrives (`drop_async`), and an `async_call` destroyed with an untaken success settles it (`async<T>::abandon()`): never drop one another way. Before destroying a sandbox that may have pending calls, hand them on with `release_async()` (the host does) and pump the returned `async_leftovers`.
- Effects that can be reverted out of order (variable writes, patch layers) live in process-wide per-target stacks (`detail/var_layers.hpp`, `detail/patch_layers.hpp`); the ledger only owns and orders them. A reverted write finds its layer from the newest end.
- Writes through views to host memory (`view_journal.cpp`): one `region_layer` effect per target (a `view_source`: the same binding called with equal arguments, `same()`) and per running code (`context`, `current_owner()`), made at its first write; each unit (a span element, an object byte) keeps its original the first time that layer writes it, in 4 KiB pages. Layers of one target stack process-wide (a registry under one mutex) and hand originals to the next newer layer that wrote the same unit, like `var_layers`; undo re-resolves the target (moved memory is restored where it is now, gone memory has nothing to restore). A node caches its layer while the registry's epoch (bumped whenever a layer goes away), the context and the owner are unchanged: the write itself takes no lock, so the memory a view writes and its journal belong to one thread at a time, like the memory. Buffers are script state and never journaled; writes need `role::kPatch` only for host memory.
- Lib variables: RHP's reads, writes and undos of one variable are serialized by one lock per variable; a small trivially copyable one (`lock_free_var<T>`: `std::atomic_ref<T>` always lock-free and aligned) is read with an atomic load and written with an atomic store instead of taking the lock for reads. The application's own accesses are its own business.
- A sandbox and its Lua state belong to one thread (the one that calls `pump()`). Patch points may be hit from any thread; a layer owned by another thread is skipped (counted in `off_thread_misses()`). Events fired off that thread are queued (`limits.event_queue`).
- The debugger with breakpoints only turns line events on per function (`scope_lines`, `internals::set_line_events`): only functions whose lines hold a breakpoint get them, switched on call and return events, with the last answer cached by source and line range. A chunk named without `@` / `=` keeps them on; a step, a pause or coverage watch every line. Inspection never runs Lua.
- Test tools never change what a script does: metering credits instructions to budgets too, swaps of lib members are ledger effects, the `__rhp_test` bridge exists only in the scratch environment of a sandbox with `enable_testing`. `exec_cached` is for trusted sources only (bytecode is never checked).
- Bytecode is loaded only from a `trusted_bytecode` (`load` / `reload`), which callers make from what `compile_module` produced in this process or from an entry they authenticated (the release store's MAC'd cache, [compiled-chunk cache](../../../Docs/decisions/compiled-chunk-cache.md)); every other load (exec, a module's source, Lua's `load`) is text only, and nothing from the wire is ever bytecode. A trusted chunk must be a main chunk compiled under the module's name, else it is set aside and the source parsed (`sandbox_stats::bytecode_rejected`).
- `RHP_ENABLE=OFF`: `puc_lua/` is not compiled, Lua is not fetched, `sandbox_disabled.cpp` reports `kDisabled`, patch points are direct calls, `lua_event::fire` is a no-op. The DSL, the ledger and `api::describe` still build.
